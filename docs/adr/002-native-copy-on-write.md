# 002 Require working copy-on-write operations

A filesystem name or feature flag cannot guarantee that a particular clone will work. Probe the destination's filesystem with a newly created file pair and verify the output bytes before selecting the clone engine. Per-file failures still go through Git for tracked files. Warm caches require native sharing. Separate inodes keep content and mode changes private to each worktree.

- **Linux.** Use `FICLONE` with owned file descriptors and a newly created destination. Open donors without following a final symlink or blocking if a FIFO replaced a file. OpenZFS may refuse a clone while the source is dirty. Sync only on retry because an unconditional sync can wait for a whole Btrfs transaction.
- **macOS.** Use `fclonefileat` with `CLONE_NOFOLLOW`. APFS copies BSD flags and xattrs, so reset tracked clones to Git checkout metadata. If metadata reset fails, discard the clone and let Git write it. Sample the process umask before spawning worker threads because reading it requires temporarily changing process-wide state. The flags and ioctl definitions follow `sys/clonefile.h` and Linux's `include/uapi/linux/fs.h`.
- **Windows.** Enable ReFS cloning by explicit request. Check volume block-refcount support and verify a 64 KiB probe. Open the donor denying other writers and request the write access needed by `FlushFileBuffers`. Flushing before cloning addresses the [zero-filled clone observed by Git LFS](https://github.com/git-lfs/git-lfs/issues/6312). Size the destination first, match integrity-stream and sparse attributes, and submit cluster-aligned ranges below 4 GiB. Round the last range to the cluster boundary while retaining the destination's original byte length. For seeded index metadata, Git for Windows uses creation time for ctime, last-write time for mtime, and zero for device, inode, uid, and gid. [Microsoft's block cloning requirements](https://learn.microsoft.com/en-us/windows-server/storage/refs/block-cloning)

Keep descriptors and handles alive throughout native calls. Unix path arguments pass through `CString`, and Windows bindings receive NUL-terminated UTF-16. Synchronous `DeviceIoControl` uses the documented native input and output structures and keeps the buffers alive until it returns. A failed clone can remove only the new file it owns, after closing the handle for Windows sharing semantics. The destination goes into the Git index only after [checkout verification](001-verified-git-checkout.md).

Linux `reshare` uses `FIDEDUPERANGE`, which compares both ranges while holding kernel locks and deduplicates only equal bytes. This preserves inodes and timestamps and therefore the worktree's index stat entries. `FIEMAP` can skip already shared files when both mappings report shared extents at matching logical and physical offsets. Test filesystem identity and inode identity before asking the kernel to deduplicate. Respect the Linux UAPI layouts and keep the flexible-array request allocation alive throughout each ioctl. The errno classification and probe draw on lukeed/lane, while the Linux dedupe layout and chunking were adapted from leostera/git-twig. The dedupe idea came from huntharo/git.
