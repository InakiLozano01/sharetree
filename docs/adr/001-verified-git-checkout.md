# 001 Use Git to finish a verified reflink checkout

A worktree created by sharetree must match one created by `git worktree add`. Git already owns registration, reference updates, checkout conversions, sparse checkout, and hooks. Sharetree registers a worktree with `--no-checkout`, creates only an eligible subset of its regular files, seeds a temporary index with those files, then lets Git populate the target tree. Git compares cached stat data before deciding whether to rewrite a file. The seeded index carries the clones' actual stat data so Git can preserve their shared blocks.

- Look for clean donors on the same filesystem. Match by blob ID so moves and renames remain eligible. The current, deepest enclosing worktree gets priority among candidates. An early scan of the donor overlaps registration, but its results apply only when the registered `HEAD` matches the commit scanned. Read-only Git calls disable optional locks so that scanning cannot refresh the donor's index. Overrides such as `GIT_DIR` can make Git see another repository even when invoked in the worktree, so those calls use stock Git behavior instead of assembling a partial checkout.
- Git reads attributes from the target commit. Defer converted paths, ambiguous filenames, and options or repository settings that require Git to manage the entire operation. An undefined optional filter does not transform content. A required filter whose driver is unavailable needs Git to report the checkout error. Git may accept checkout switches by unambiguous prefix, so the preflight recognizes those forms too.
- Treat a donor's index as a filter. Recheck the open donor after cloning, hash the clone as a Git blob, and check the clone's type, size, mode and timestamps before writing an entry. Keep SHA-1 collision detection because Git applies it. The SHAttered test feeds the raw fixture to the hasher because Git's blob header shifts the collision blocks. See [Third-party notices](../../THIRD_PARTY_NOTICES).
- Publish the v2 seed through `index.lock` and rename. An already-created index belongs to Git. The seed is disposable because the next Git command rebuilds it. The seed write skips an `fsync` that once cost 1.4 s on a Btrfs kernel checkout. Keep format checks covered by the v2 index tests, including raw byte order, timestamp truncation, entry padding and repository-specific checksum.
- Serialize sharetree registrations with a lock in Git's common directory. Concurrent stock Git registrations have encountered half-written `commondir` files. Stock Git does not participate in sharetree's advisory lock. Roll back an unfinished registration on checkout failure, keeping any branch Git created. Once checkout succeeds, a failing post-checkout hook returns its status and leaves the populated worktree in place.

The default clone threshold of 2,049 bytes comes from Btrfs's default inline extent limit. Fresh clones start with a cold page cache. The measured approach uses separate clone and verification phases and more readers than cloners. The [benchmark notes](../../README.md#benchmarks) record the effects of sharded attribute reads, sequential readahead, hashing as clones arrive, and checking out remaining files while hashing. The drop-in tests check that Git sees the same files and index as stock Git. Create the sharetree checkout first so the stock one cannot become a donor. `git diff-files` verifies stat validity without refreshing the index first. The dirty-donor regression records an old mtime before restoring it after a same-size edit. The old timestamp avoids Git's additional rehash when an index entry looks racily clean.

The registration, seeded index, and test design came from josharian/git-cow-worktree. Donor scoring and conversion rules draw on leostera/git-twig, and the donor re-stat idea came from huntharo/git. [Third-party notices](../../THIRD_PARTY_NOTICES)
