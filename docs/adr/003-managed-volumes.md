# 003 Keep seeds on their managed volume

Reflinks cannot cross filesystems. On a host without suitable native support, a user can opt into a copy-on-write volume. Keep a detached seed checkout per repository on that volume so the first worktree pays for an ordinary checkout and subsequent worktrees have a local donor. Advance a clean seed to the target commit and keep the repository's worktrees locked against Git pruning while the volume is offline. A generated alias keeps the requested path usable across mounts.

- Linux uses a sparse Btrfs or reflink-enabled XFS image. Set NOCOW on an image hosted on Btrfs to avoid extra fragmentation from nesting copy-on-write filesystems. The first attach and mount can use udisks via the active user's polkit session. The generated user unit retries while that session becomes available and carries the exact sharetree config path. Where polkit does not grant access, print root-once fstab instructions for the user to apply. Escape systemd and fstab fields according to their separate rules. By default reserve a fraction of free space as the sparse file's cap and observe XFS's formatting minimum.
- Windows uses a dynamically expanding ReFS Dev Drive VHDX and an elevated setup script. The logon task keeps the drive usable across boot, since Windows does not reattach VHDs itself. Windows PowerShell 5.1 needs a UTF-8 BOM for a UTF-8 script file, and `-EncodedCommand` expects UTF-16LE before Base64. The documented minimum is 50 decimal GB. [Microsoft's Dev Drive requirements](https://learn.microsoft.com/en-us/windows/dev-drive/)
- Explicit choices take precedence. If a repository has a configured volume and no choice, ask only with interactive input and error streams and no `SHARETREE_NO_PROMPT`. Without an interactive answer, continue with Git and show how to opt in. Persist a repository preference only for an explicit always or never answer.

The [setup instructions](../../README.md#filesystems-without-reflinks-ext4-ntfs) cover volume placement, configuration precedence, and teardown.
